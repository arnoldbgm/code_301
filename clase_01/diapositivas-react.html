¿Qué es React?

React es una biblioteca de JavaScript creada por Meta (Facebook) en 2013 para construir interfaces de usuario que se actualizan automáticamente cuando los datos cambian.

📌 Escribís HTML y lógica en un mismo archivo. React se encarga de mostrar y sincronizar todo en pantalla sin que toques el DOM manualmente.

Línea de tiempo: 2011 nace en Facebook · 2013 open source · 2019 Hooks · 2024 React 19 · 2026 domina el mercado con ~70%

⚙️ ¿Cómo funciona React?

Solo un concepto clave para arrancar:

React mantiene un Virtual DOM: una representación liviana del HTML en JavaScript. Cuando los datos cambian, React compara la versión nueva con la anterior y actualiza solo las partes que cambiaron en el DOM real.

📦 Estado cambia → 🔄 React recalcula → 🔍 Compara cambios → ⚡ Actualiza solo lo distinto

💡 No necesitás memorizar esto ahora. Solo recordá: si algo no se actualiza en pantalla, es porque React no detectó el cambio (casi siempre es porque modificaste el estado incorrectamente).

🧱 Componentes — el corazón de React

Un componente es una función que devuelve HTML. Es la unidad básica de construcción en React, como un ladrillo en una construcción.

Saludo.jsx
function Saludo() {
  return <h1>Hola, mundo 👋</h1>;
}

export default Saludo;

✅ 4 líneas. Una función. Eso es un componente.

App.jsx
import Saludo from './Saludo';

function App() {
  return (
    <div>
      <Saludo />
      <Saludo />
      <Saludo />
    </div>
  );
}

🎨

JSX

JSX es una extensión de sintaxis que permite escribir HTML dentro de JavaScript. Las llaves { } abren una "ventana" a JavaScript.

Tarjeta.jsx
function Tarjeta() {
  const nombre = 'Martina';
  const edad = 22;

  return (
    <div className="tarjeta">
      <h1>{nombre}</h1>
      <p>Edad: {edad}</p>
      <p>El año que viene: {edad + 1}</p>
    </div>
  );
}

💡 Las llaves { } ejecutan cualquier expresión de JavaScript: variables, operaciones aritméticas, funciones, ternarios.

⚠️ Diferencias HTML vs JSX

HTMLJSXMotivo
class=""className=""class es palabra reservada en JS
for=""htmlFor=""for es palabra reservada en JS
style="color:red"{{color:'red'}}JSX recibe un objeto JavaScript
onclick="fn()"onClick={fn}Se pasa la función, no un string
autofocusautoFocuscamelCase en atributos
tabindex="0"tabIndex={0}camelCase en atributos

Regla general: camelCase y valores con llaves cuando no sean strings. Las primeras veces te vas a olvidar, pero con la práctica se vuelve automático.

📦 Props — datos entre componentes

Las props son los argumentos que recibe un componente. Así como una función recibe parámetros, un componente recibe props.

Tarjeta.jsx
function Tarjeta({ nombre, edad }) {
  return (
    <div>
      <h3>{nombre}</h3>
      <p>{edad} años</p>
    </div>
  );
}
App.jsx
function App() {
  return (
    <div>
      <Tarjeta nombre="Ana" edad={25} />
      <Tarjeta nombre="Luis" edad={30} />
      <Tarjeta nombre="Sofía" edad={22} />
    </div>
  );
}
⬇️ Los datos fluyen de padre a hijo

useState — estado local

El estado es la memoria del componente. Permite que el componente recuerde valores que pueden cambiar con el tiempo.

Contador.jsx
import { useState } from 'react';

function Contador() {
  const [contador, setContador] = useState(0);

  return (
    <div>
      <p>{contador}</p>
      <button onClick={() => setContador(contador + 1)}>+1</button>
    </div>
  );
}

useState devuelve un par: el valor actual y una función para modificarlo. Nunca se asigna directamente, siempre se usa la función actualizadora.

🔑 Estructura de useState


  const [contador, setContador] = useState(0);
  //       ▲          ▲              ▲
  //       │          │              └── valor inicial
  //       │          └── función para actualizar (única forma de cambiar)
  //       └── valor actual (solo lectura)
❌ Incorrecto

contador = 5;

React no detecta la asignación directa. La pantalla no se actualiza.

✅ Correcto

setContador(5);

React detecta el cambio y vuelve a renderizar el componente.

📝 Input controlado

Patrón fundamental: el valor del input está sincronizado con el estado de React.

NombreForm.jsx
function NombreForm() {
  const [nombre, setNombre] = useState('');

  return (
    <div>
      <input
        type="text"
        value={nombre}
        onChange={(e) => setNombre(e.target.value)}
        placeholder="Escribí algo..."
      />
      <p>Escribiste: {nombre}</p>
    </div>
  );
}

Flujo: usuario escribe → onChange captura el valor → setNombre actualiza el estado → React re-renderiza → el input muestra el nuevo valor.

🖱️ Eventos

Evento simple
function Boton() {
  function handleClick() {
    alert('Hiciste click');
  }

  return (
    <button onClick={handleClick}>
      Click
    </button>
  );
}

// Sin paréntesis — se pasa
// la función, no se la llama
Con parámetros
function Lista() {
  const items = ['A', 'B', 'C'];

  function elegir(item) {
    alert(`Elegiste: ${item}`);
  }

  return (
    <ul>
      {items.map(i =>
        <li key={i}
          onClick={() => elegir(i)}
        >{i}</li>
      )}
    </ul>
  );
}

📋 Formulario completo

Formulario.jsx
function Formulario() {
  const [email, setEmail] = useState('');

  function handleSubmit(e) {
    e.preventDefault(); // Evita que la página recargue
    alert(`Email ingresado: ${email}`);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
        placeholder="tu@email.com"
      />
      <button type="submit">Enviar</button>
    </form>
  );
}
⚠️ e.preventDefault() es obligatorio en formularios. Sin esto, la página recarga y se pierde todo el estado.

🔀 Renderizado condicional

Mostrar contenido diferente según una condición.

Con if / else

function Mensaje({ logeado }) {
  if (logeado) {
    return <p>Bienvenido 🎉</p>;
  }
  return <p>Iniciá sesión 🔐</p>;
}

Con operador ternario

{producto.stock > 0
  ? <span>✅ En stock</span>
  : <span>❌ Sin stock</span>
}

Con AND lógico

{mensaje && <div>{mensaje}</div>}
// Si mensaje es null/undefined/vacío
// → no se renderiza nada

📋 Listas

ListaTareas.jsx
function ListaTareas() {
  const tareas = [
    { id: 1, texto: 'Estudiar React' },
    { id: 2, texto: 'Practicar hooks' },
    { id: 3, texto: 'Armar un proyecto' },
  ];

  return (
    <ul>
      {tareas.map(t => <li key={t.id}>{t.texto}</li>)}
    </ul>
  );
}
❌ key={indice}

Si el orden de la lista cambia, React no puede identificar correctamente los elementos. Genera bugs difíciles de rastrear.

✅ key={id}

Usá un ID único y estable. React identifica cada elemento y solo actualiza lo necesario.

🏗️ Composición de componentes

Componentes pequeños se combinan para formar interfaces complejas. Es la forma de trabajar en React.

function Avatar({ url, nombre }) {
  return <img src={url}
    alt={nombre} width={50} />;
}

function Info({ nombre, email }) {
  return (
    <div>
      <h3>{nombre}</h3>
      <p>{email}</p>
    </div>
  );
}
function TarjetaUsuario({ usuario }) {
  return (
    <div style={{ display: 'flex',
      gap: '1rem' }}>
      <Avatar url={usuario.avatar}
              nombre={usuario.nombre} />
      <Info nombre={usuario.nombre}
            email={usuario.email} />
    </div>
  );
}

💡 Buenas prácticas

Señales de que un componente debería dividirse:

📏 Más de 80 líneas de código
🎭 Maneja estados que no están relacionados entre sí
🧵 Mezcla lógica de negocio con presentación
🤷 Es difícil ponerle un nombre porque hace "demasiadas cosas"
✅ Cada componente debería hacer una sola cosa. Si no sabés cómo nombrarlo, probablemente sea porque hace demasiado. Dividilo.
